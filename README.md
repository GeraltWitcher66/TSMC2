# فیلتر بورس ایران

وب‌اپ فارسی و راست‌به‌چپ برای بررسی فهرست‌های شخصی نمادهای بورس، فرابورس و بازار پایه. پنجره آغازین برنامه فقط معرفی کوتاه برنامه را نمایش می‌دهد.

> این مخزن شامل نسخه توسعه محلی با موتور جدید واگرایی RD/HD است. نسخه حاضر در این مرحله روی Cloudflare منتشر نشده است؛ استقرار و تأیید داده زنده مستقل از آزمون‌های محلی انجام می‌شود.

## معماری و داده‌ها

مسیرهای سروری/Worker داده را از زروان و TSETMC دریافت می‌کنند و نتیجه محاسبات را به رابط می‌دهند. مرورگر عمدتاً APIهای همین برنامه را فراخوانی می‌کند؛ اگر Client Type یا تغییرات سهامداران در Worker در دسترس نباشد، مسیر مستقیم و زمان‌دار مرورگر به TSETMC فعال می‌شود. مشخصات نمادهای محدوده انتخابی از زروان دریافت می‌شود. اگر هر دو شبکه ناموفق باشند، آخرین Snapshot معتبر با تاریخ خودش نمایش داده می‌شود.

- تاریخچه قیمت: دریافت دسته‌ای Zarvan؛ برای درخواست‌های حداکثر چهار نمادی، تاریخچه رسمی TSETMC نیز ادغام می‌شود و روی تاریخ مشترک اولویت دارد. درخواست‌های مرورگر ۲۰ نمادی هستند و بررسی رسمی همه تاریخچه‌ها را انجام نمی‌دهند.
- قیمت جلسه: `GetClosingPriceInfo` رسمی، با چهار درخواست هم‌زمان و مهلت چهار ثانیه برای هر نماد، قیمت دارای تاریخ و حجم را تأمین می‌کند. قیمت رسمی جلسه بر تاریخچه همان روز اولویت دارد. Snapshot تاریخ‌دار زروان نیز قابل استفاده است؛ تاریخ صفر با تاریخ امروز جایگزین نمی‌شود. اگر قیمت تاریخ‌دار دریافت نشود، تاریخچه معتبر حفظ و محدودیت تازگی در ردیف گزارش می‌شود.
- تغییر تعداد سهام و افزایش سرمایه: TSETMC، برای تاریخچه‌های دارای شکاف بالقوه حداقل ۸٪، با سقف ۱۲ نماد در هر درخواست؛ شکست دریافت به معنی تأیید نبود رویداد نیست.
- سهامداران عمده و اطلاعات معاملاتی فهرست‌ها: Zarvan/TSETMC؛ حجم خرید/فروش حقیقی و حقوقی از `GetClientTypeAll` رسمی خوانده می‌شود.
- خرید/افزایش سهامدار عمده حقیقی: دیتاست رسمی `GetShareHolderChanges` و اطلاعات ابزار TSETMC، با صفحه‌بندی ۲۰ ابزار در هر درخواست. اسکن واچ‌لیست فقط مشخصات نمادهای همان فهرست را می‌خواند. تاریخ صفحات کنترل می‌شود و صفحه شکست‌خورده با Snapshot تاریخ دیگر ترکیب نمی‌شود.
- پاسخ‌های حساس به بازار با `no-store/no-cache` برگردانده می‌شوند تا داده قدیمی مرورگر جای داده تازه را نگیرد.

آخرین تاریخ نمایش‌داده‌شده از خود داده بازار استخراج می‌شود. تعطیلی یا آخرهفته به‌تنهایی به معنی stale بودن آخرین جلسه معتبر نیست. شکست یک نماد یا یک دسته، نتیجه سالم سایر نمادها را از بین نمی‌برد. فهرست زرد/نارنجی از نمادهای ذخیره‌شده کاربر استفاده می‌کند؛ API مستقل `market-color` در رابط فعلی فراخوانی نمی‌شود.

Cron و کش مشترک Cloudflare در این نسخه عمداً اضافه نشده‌اند. تازه‌سازی سمت سرور و هنگام درخواست انجام می‌شود؛ این انتخاب خطر بازگشت داده قدیمی را کم می‌کند. در صورت افزایش تعداد کاربران می‌توان بعداً کش مشترک را با TTL و ابطال وابسته به جلسه بازار اضافه کرد.

## امکانات اصلی

- فیلترهای مستقل ۹۰ و ۱۸۰ روز تقویمی.
- انتخاب مستقل افت از سقف ۳۰، ۶۰ و ۹۰ روز تقویمی، همراه با تغییر اعداد و توضیح بازه جدول.
- قیمت ابتدای دوره، سقف دوره، آخرین پایانی، بازده و افت از سقف با تاریخ و واحد ریال.
- RSI استاندارد ۱۲روزه Wilder (روی آخرین معامله) و فیلتر RSI کمتر یا مساوی ۳۰. RSI مخصوص واگرایی به‌صورت مستقل بر پایه قیمت پایانی محاسبه می‌شود.
- کنترل رسمی افزایش سرمایه و تعدیل تاریخچه؛ شکاف بدون تغییر رسمی تعداد سهام تأیید نمی‌شود.
- مدیریت سه فهرست «حقیقی»، «زرد/نارنجی» و «دلخواه»، ورود/خروج TXT، حذف تکرار و حفظ ترتیب.
- منتخب‌های مشترک بین فهرست‌ها.
- اسکن کل بازار برای شمارش ردیف‌های دقیق «شخص حقیقی» در سهامداران عمده.
- تب بیشترین‌ها با چهار محدوده حقیقی، زرد/نارنجی، دلخواه و مجموع فهرست‌ها بدون تکرار. چهار کارت رتبه‌بندی حداکثر ۱۰ نتیجه دارند؛ کارت پنجم تغییرات سهامدار حقیقی، هر سهامدار را با تعداد سهم فعلی، مالکیت و افزایش سهم در ردیف جدا نشان می‌دهد.
- سه کارت اول: معیار اصلی، نماد، آخرین معامله و پایانی به ریال همراه با درصد تغییر، و اختلاف به واحد درصد.
- ستون «خرید حقیقی» بلافاصله بعد از واگرایی، با تعداد خریداران عمده حقیقی به‌صورت سبز و تعداد فروشندگان عمده حقیقی به‌صورت قرمز.
- تب «خرید / افزایش سهام سهامداران عمده حقیقی» با پنج محدوده: سه فهرست جدا، مجموع واچ‌لیست‌ها و کل بازار؛ تعداد فعلی/قبلی، درصد مالکیت، افزایش سهم، تاریخ و بازار را نمایش می‌دهد.

## محاسبات دوره

```text
بازده دوره = (آخرین پایانی ÷ پایانی ابتدای دوره − ۱) × ۱۰۰
افت از سقف = (۱ − آخرین پایانی ÷ بیشترین قیمت دوره) × ۱۰۰
```

تاریخ مبنا دقیقاً ۹۰ یا ۱۸۰ روز تقویمی قبل از جدیدترین کندل معتبر است و اولین جلسه موجود در تاریخ مبنا یا پس از آن انتخاب می‌شود. قیمت‌های قبل از تغییر رسمی تعداد سهام با نسبت سهام قدیم به جدید تعدیل می‌شوند.

## دو محاسبه P/E

1. `EPS × P/E گروه`: قیمت مرجع ریالی، گرد‌شده به نزدیک‌ترین ۱۰ ریال. درصد اختلاف آن با آخرین پایانی نمایش داده می‌شود و فقط وقتی قیمت مرجع بالاتر است حالت مثبت می‌گیرد.
2. `P/E سهم / P/E گروه`: دو مقدار اصلی کنار هم نمایش داده می‌شوند؛ این عنوان به معنی تقسیم ریاضی نیست. شرط مثبت دقیقاً `P/E سهم > 0` و `P/E سهم < P/E گروه` است.

مقادیر صفر، منفی، ناموجود، `NaN` و `Infinity` وارد خروجی مثبت نمی‌شوند.

## واگرایی

موتور واگرایی بر اساس **دو پیوت تأییدشده** از سقف/کف روزانه و RSI(۱۲) ساخته‌شده از **قیمت پایانی تعدیل‌شده** است. RSI جدول اصلی همچنان مستقل و بر مبنای آخرین معامله روز نمایش داده می‌شود. صرفاً خلاف‌جهت بودن قیمت و RSI در دو روز متوالی، واگرایی محسوب نمی‌شود.

- **واگرایی مثبت (صعودی):** کف دوم قیمت پایین‌تر و کف RSI متناظر بالاتر باشد.
- **واگرایی منفی (نزولی):** سقف دوم قیمت بالاتر و سقف RSI متناظر پایین‌تر باشد.
- هیچ حالت دیگری واگرایی نیست؛ واگرایی مخفی وجود ندارد.
- RSI متناظر از کمینه/بیشینه نزدیک پیوت قیمت در فاصله حداکثر دو جلسه معاملاتی گرفته می‌شود؛ تاریخ RSI اگر متفاوت باشد، در جزئیات مشخص است.
- پیوت تخت (سقف/کف برابر در دو روز متوالی) یک پیوت است و اولین کندل آن پیوت محسوب می‌شود: سمت چپ مقایسه اکید است و سمت راست می‌تواند مساوی باشد.
- تنها کندل‌های **بسته‌شده** وارد تحلیل می‌شوند؛ پیوت با دو کندل در سمت راست قطعی می‌شود. نامعتبر بودن تاریخ، قیمت یا OHLC و شکاف افزایش سرمایه فاقد مدرک مانع صدور الگو است.
- نمادی که آخرین کندلش از آخرین جلسه بازار قدیمی‌تر است برچسب «نماد بسته» می‌گیرد و در شمارنده‌های واگرایی حساب نمی‌شود.
- واگرایی صرفاً یک **هشدار تحلیلی** است. تأیید دوطرفه پیوت معادل تأیید برگشت یا ادامه روند نیست. MACD و واگرایی زمانی در موتور فعلی فعال نیستند.

تنظیمات پیش‌فرض در `PATTERN_DEFAULTS` و `DIVERGENCE_DEFAULTS` متمرکز شده‌اند:

| تنظیم | مقدار |
|---|---:|
| پنجره پیوت | ۲ کندل در هر سمت |
| حداقل تغییر قیمت | ۰٫۳٪ |
| حداقل اختلاف RSI | ۱ واحد |
| حداقل فاصله پیوت | ۵ کندل |
| حداکثر فاصله پیوت | ۵۰ کندل |
| تازگی سیگنال | ۱۰ کندل |
| هم‌ترازی RSI با پیوت قیمت | حداکثر ۲ کندل |
| مبنای RSI واگرایی (`rsiSource`) | قیمت پایانی (`close`)، قابل تغییر به `last` |
| حداقل تاریخچه اولیه | ۲۴ کندل بسته‌شده |

آزمون‌های `tests/divergence-patterns.test.mjs` دو نوع الگو، حذف حالت‌های دیگر، پیوت تخت، تازگی سیگنال، داده ناقص و نمونه‌های قیمتی ساختگی را پوشش می‌دهند. فایل‌های Snapshot واقعی قبلی برای بررسی تاریخچه و سازگاری داده نگهداری شده‌اند؛ طبقه‌بندی‌های مربوط به موتورهای قدیمی، تأیید خودکار نتایج این موتور جدید محسوب نمی‌شوند.

## خرید سهامدار عمده حقیقی

- در صورت وجود Snapshot قبلی: `تغییر = تعداد فعلی − تعداد قبلی` محاسبه می‌شود؛ افزایش برای شمارش خریدار و کاهش برای شمارش فروشنده استفاده می‌شود.
- اگر Snapshot قبلی موجود نباشد اما منبع رسمی مقدار مثبت تغییر سهم ارائه کند، رکورد با مدرک `official` پذیرفته می‌شود و مقدار قبلی ناموجود نمایش داده می‌شود.
- بدون Snapshot قبلی و بدون مدرک رسمی غیرصفر، خرید یا فروش حدس زده نمی‌شود.
- فقط نام نرمال‌شده دقیق «شخص حقیقی» پذیرفته می‌شود؛ شرکت، صندوق، بانک، سرمایه‌گذاری و سایر حقوقی‌ها حذف می‌شوند.
- درصد مالکیت فقط از `تعداد فعلی ÷ کل سهام شرکت × ۱۰۰` محاسبه می‌شود؛ کل سهام نامعتبر یعنی درصد ناموجود.
- جدول کامل «خرید حقیقی عمده» همچنان فقط افزایش‌های مثبت را با تعداد سهم و درصد مالکیت نشان می‌دهد؛ ستون فشرده جدول ۹۰/۱۸۰ تعداد خریدار و فروشنده را نشان می‌دهد.

## از صف فروش به مثبت

نماد فقط وقتی وارد کارت چهارم می‌شود که هر سه شرط هم‌زمان برقرار باشند: کمینه روز به کف مجاز روز رسیده باشد، آخرین قیمت نسبت به دیروز مثبت باشد و قیمت پایانی هنوز منفی مانده باشد. مطابق اعداد تصویر کارفرما، اختلاف برابر درصد آخرین معامله منهای درصد پایانی است؛ مثال +۲٫۶۸ و −۲٫۹۲ برابر ۵٫۶ واحد درصد. حجم خرید/فروش حقیقی از Client Type رسمی خوانده می‌شود؛ در صورت نبود داده مقدار ناموجود نمایش داده می‌شود.

## اجرای محلی

پیش‌نیاز: Node.js `22.15.0` یا جدیدتر (آزموده‌شده با Node 24). اجرای محلی ویندوز از `tools/start.mjs` برای سازگاری مسیر فایل‌های استاتیک Vinext استفاده می‌کند.

```bash
npm ci
npm run dev
```

برای اجرای خروجی Production محلی روی پورت ۳۰۰۰:

```bash
npm run build
PORT=3000 HOST=127.0.0.1 npm run start
```

آدرس: `http://127.0.0.1:3000/`

## Cloudflare برای انتشار بعدی

پیکربندی Worker در `wrangler.toml` و `worker/index.ts` قرار دارد. build پیکربندی نهایی را در `dist/server/wrangler.json` می‌سازد و Wrangler از طریق `.wrangler/deploy/config.json` به آن هدایت می‌شود. Asset binding با نام `ASSETS` است. Secret اختصاصی برنامه لازم نیست؛ حساب Wrangler باید برای انتشار وارد شده باشد. کاربر انتشار این تغییرات را پس از تست مجاز کرده است:

```bash
npm run lint
npm run typecheck
npm test
npx wrangler deploy --dry-run
npx wrangler deploy
```

نسخه آماده استقرار وابستگی به پورت محلی ندارد. آزمون‌های واحد با `npm test` اجرا می‌شوند؛ برای آزمون تعامل واقعی مرورگر و پنجره واگرایی، ابتدا سرور محلی را اجرا کرده و سپس `node --import ./tests/register-typescript.mjs tests/divergence-ui-browser.mjs` را فراخوانی کنید. این سناریو از داده شبیه‌سازی‌شده استفاده می‌کند و تأیید اطلاعات زنده بورس محسوب نمی‌شود.

## محدودیت‌های شناخته‌شده

- در دسترس‌نبودن یا تأخیر منابع خارجی می‌تواند برخی نمادها را موقتاً ناقص کند؛ UI وضعیت ناقص را گزارش می‌کند.
- دیتاست کل‌بازار سهامداران حقیقی هویت اشخاص را عموماً به‌صورت ناشناس «شخص حقیقی» منتشر می‌کند؛ تفکیک افراد فقط تا حد شناسه‌های عمومی منبع ممکن است.
- دو پیشنهاد اختیاری «کدبه‌کد حقوقی به حقیقی» و «ورود پول هوشمند» تا زمان تعیین فرمول و آستانه مورد تأیید کارفرما به‌عنوان فیلتر جدید فعال نشده‌اند؛ داده پایه حقیقی/حقوقی برای توسعه بعدی آماده است.
- کش مشترک/Cron برای کاهش تعداد درخواست‌های upstream به نسخه آینده موکول شده است.
- این ابزار غربال‌گری است و توصیه خرید یا فروش نیست.

## استقرار

نسخه حاضر به‌صورت محلی Build و آزمون شده و **هنوز روی Cloudflare منتشر نشده است**. برای انتشار، ابتدا حساب مالک Worker، مجوزها، نسخه فعال و امکان بازگشت به نسخه قبلی بررسی شوند. بررسی محلی یا پاسخ HTTP 200 نسخه قبلی، تأیید عملکرد نسخه جدید روی Production نیست.
